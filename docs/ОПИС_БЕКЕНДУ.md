# Опис бекенду персональної електронної бібліотеки

Документ для захисту курсової. Пояснює, **що робить бекенд**, **де лежить код**, **які технології** і **як дані зберігаються**. Написано максимально просто.

---

## 1. Що таке бекенд у цьому проєкті (простими словами)

Бекенд — це «кухня» застосунку: уся логіка, база даних і робота з файлами книг.

Він **не** є окремим веб-сервером з адресою типу `http://localhost:8000`. Тут **немає REST API, JWT і браузерних запитів**.

Як це працює насправді:

1. Користувач натискає кнопку в графічному інтерфейсі (фронтенд на PySide6).
2. Інтерфейс викликає звичайний Python-метод, наприклад `container.books.list()` або `container.quotes.create(...)`.
3. Бекенд виконує роботу: читає/пише SQLite, копіює файли, парсить PDF/EPUB.
4. Повертає результат у GUI.

Репозиторій бекенду:

```
D:\project\electronic-library-backend
```

Фронтенд підключає його через `sys.path` (див. `electronic-library-frontend/gui/bootstrap.py`) і викликає:

```python
from app.main import init_backend
container = init_backend(data_dir)
```

## 3. Архітектура шарів

Бекенд побудований шарами. Кожен шар має свою роботу і **не повинен** робити чужу.

```
GUI (фронтенд)
    ↓ викликає методи
AppContainer          ← «пульт» з усіма сервісами
    ↓
Services              ← бізнес-логіка (імпорт, цитати, читач…)
    ↓
Repositories          ← доступ до БД (CRUD)
    ↓
SQLAlchemy Models     ← таблиці
    ↓
SQLite (library.db)

Окремо:
Readers  — відкрити PDF/EPUB, текст, сторінки
Storage  — файли книг, обкладинки, кеш, шляхи
```

### Навіщо так

- **GUI** лише показує кнопки й екрани.
- **Services** вирішують «що робити» (імпортувати книгу, зберегти цитату).
- **Repositories** лише читають/пишуть у БД.
- **Readers** знають формат файлу.
- **Storage** знає, куди класти файли на диску.

Це і є модульна архітектура з постановки задачі: розділення GUI, бізнес-логіки, БД, файлів і читача.

## 4. Точка входу та контейнер залежностей

### `app/main.py`

Функція `init_backend(data_dir=None)`:

1. Налаштовує логування.
2. Створює `AppConfig` (шляхи до `data/`).
3. Викликає `build_container(config)`.
4. Повертає готовий `AppContainer`.

Клас `AppContainer` — один об’єкт на весь час роботи програми. У ньому зібрані всі сервіси:

| `books` | `BookService` | CRUD книг, статус, рейтинг, обкладинка |
| `imports` | `ImportService` | імпорт PDF/EPUB з диска |
| `reader` | `ReaderService` | відкрити книгу, рендер, TOC, зберегти позицію |
| `reading` | `ReadingService` | прогрес читання, сесії |
| `quotes` | `QuoteService` | цитати |
| `bookmarks` | `BookmarkService` | закладки |
| `notes` | `NoteService` | нотатки |
| `reviews` | `ReviewService` | відгуки |
| `collections` | `CollectionService` | колекції / «папки» книг |
| `search` | `SearchService` | фільтри + FTS-пошук |
| `statistics` | `StatisticsService` | статистика, календар, цілі |

## 7. Моделі даних (що зберігається в БД)

Усі моделі: `app/models/`.

### 7.1. Користувач — `User` (`user.py`)

Локальний акаунт. Пароль зберігається як **bcrypt-хеш**, не відкритим текстом.  
Усі книги й матеріали прив’язані до `user_id` — бібліотеки різних користувачів **ізольовані**.

### 7.2. Книга — `Book` (`book.py`) — центральна сутність

Основні поля (відповідають постановці задачі):

- назва (`title`)
- опис (`description`)
- обкладинка (`cover_path`)
- шлях до файлу (`file_path`), оригінальне ім’я, формат (`PDF` / `EPUB`)
- хеш файлу (`file_hash`) — для виявлення дублікатів
- статус прочитання (`status`): `planned`, `reading`, `completed`, `paused`, `abandoned`
- оцінка (`rating`)
- вибране / архів (`is_favorite`, `is_archived`)
- зв’язки: автори, жанри, колекції, цитати, закладки, нотатки, відгук, прогрес

### 7.3. Автор і жанр — `Author`, `Genre` (`author.py`)

Багато-до-багатьох з книгами через таблиці зв’язків у `associations.py`.

### 7.4. Колекція — `Collection` (`collection.py`)

Власні «папки» / категорії користувача для групування книг.

### 7.5. Цитата — `Quote` (`quote.py`)

Текст фрагмента, прив’язка до книги й **місця** (сторінка / позиція EPUB), тип виділення, теги, коментарі/нотатки до цитати.

### 7.6. Закладка — `Bookmark` (`bookmark.py`)

Позиція в книзі + опційний заголовок/нотатка.

### 7.7. Нотатка — `Note` (`note.py`)

Текст нотатки, локація, теги.

### 7.8. Відгук — `Review` (`review.py`)

Особистий відгук про книгу (зазвичай один на книгу).

### 7.9. Прогрес і позиція читання

- `ReadingLocation` — конкретне місце (PDF-сторінка або EPUB CFI/позиція).
- `ReadingProgress` — відсоток, поточна сторінка/розділ, посилання на локацію.
- `ReadingSession` — сесії читання для аналітики (скільки часу читали).

### 7.10. Інше

- `ImportJob` — статус імпорту файлу.
- `Tag`, `ReadingGoal`, `ReaderPreference`, `OcrPage` — у `extensions.py`.

Переліки (`enums.py`): `ReadingStatus`, `BookFormat`, `LocationType`, `ImportStatus`.

## 13. Ключові сценарії бекенду (як працює під капотом)

### 13.1. Імпорт книги

1. GUI викликає `container.imports.import_files([...])` (або `import_file`).
2. Перевірка розширення (`.pdf` / `.epub`) і розміру.
3. Обчислення SHA-256 хеша → якщо така книга вже є в цього user — дублікат.
4. Файл копіюється в `data/books/...`.
5. З файлу дістаються метадані (назва, автор…) і за можливості обкладинка.
6. Створюється запис `Book` (+ автори/жанри за наявності).
7. Текст індексується для FTS (щоб потім шукати по вмісту).
8. Статус імпорту фіксується в `ImportJob`.

### 13.2. Читання і прогрес

1. `container.reader.open_book(book_id)`.
2. За форматом відкривається PDF- або EPUB-reader.
3. GUI просить `render_page` (PDF) або `get_content` (EPUB HTML).
4. Періодично / при закритті: `reader.save_position(...)`.
5. `ReadingProgress` оновлює відсоток і останню позицію.
6. Між запусками застосунку все лежить у SQLite → прогрес не губиться.

### 13.3. Цитата

1. Користувач виділив текст у читачі.
2. GUI: `container.quotes.create(book_id, text, location=..., ...)`.
3. Запис у таблицю `quotes` з прив’язкою до місця.
4. Модуль матеріалів пізніше показує всі цитати через `quotes.list` / `quotes.search`.

### 13.4. Відгук і оцінка

- Відгук: `reviews.create` / `reviews.update`.
- Оцінка на книзі: `books.set_rating`.

### 13.5. Пошук і фільтрація

- Швидкі фільтри бібліотеки: `search.filter_books(BookFilter)` — назва, автор, жанр, статус, оцінка тощо.
- Повнотекст: `search.search_fulltext("слово")` — по вмісту, цитатах, нотатках (FTS5).

### 13.6. Колекції

`collections.create` / додати книгу в колекцію / список книг колекції — власні категорії з постановки задачі.

## 15. Персистентність (збереження між запусками)

Усе, що вимагає постановка задачі, зберігається локально:

| Дані | Де |

## 17. Що говорити на захисті одним абзацом

> Бекенд — локальний Python-модуль без веб-сервера. GUI через `AppContainer` викликає сервіси. Дані зберігаються в SQLite через SQLAlchemy. PDF обробляє PyMuPDF, EPUB — EbookLib.

## 1. Про що проєкт (одна хвилина)

### Тема

**Розробка настільного застосунку персональної електронної бібліотеки з підтримкою імпорту та опрацювання електронних книг.**

### Мета

Зробити програму мовою **Python 3**, яку можна встановити на комп’ютер і яка дозволяє:

- зібрати **особисту** бібліотеку з файлів на диску;
- **систематизувати** книги (метадані, статуси, колекції);
- **читати** PDF/EPUB всередині програми;
- зберігати **цитати, закладки, нотатки, відгуки**;
- бачити **прогрес читання**;
- щоб усе це **не зникало** після закриття програми.

### Що вийшло однією фразою

Настільний застосунок на **PySide6** з локальним Python-бекендом на **SQLAlchemy + SQLite**, який імпортує PDF/EPUB, показує їх у вбудованому читачі й зберігає всю читацьку активність у локальній базі.

## 2. Аналогія для комісії (дуже просто)

Уявіть ресторан:

| Частина ресторану | Частина проєкту | Репозиторій |
|---|---|---|
| Зал, меню, офіціанти | **Фронтенд (GUI)** — вікна, кнопки, читач | `electronic-library-frontend` |
| Кухня, склад, рецепти | **Бекенд** — логіка, БД, файли книг | `electronic-library-backend` |
| Книга замовлень | **SQLite** файл `library.db` | `data/library.db` |
| Продукти на складі | **Файли PDF/EPUB і обкладинки** | `data/books`, `data/covers` |

Гість (користувач) ніколи не заходить на кухню. Він натискає кнопку — офіціант (GUI) передає замовлення на кухню (сервіс) — кухня готує і відповідає.

**Важливо:** між залом і кухнею **немає інтернету і REST API**. Це один процес Python: GUI просто викликає функції бекенду.

## 3. Архітектура

```
run.py
  → AuthPage / MainWindow          (GUI, PySide6)
       → gui/bootstrap.py
            → init_backend()       (бекенд)
                 → AppContainer
                      → Services (books, imports, reader, quotes…)
                           → Repositories
                                → SQLAlchemy Models
                                     → SQLite
                      → Readers (PyMuPDF / EbookLib)
                      → Storage (файли на диску)
```

## 5. Технології зі списку ТЗ — що кожна робить «для дебіла»

| Технологія | Пояснення одним реченням | Без чого б не було |
|---|---|---|
| **Python 3** | Мова, якою написано і вікно, і логіку | Усього проєкту |
| **PySide6 (Qt)** | Бібліотека для кнопок, вікон, списків — « Scratch для дорослих десктоп-програм» | Інтерфейсу |
| **SQLite** | База даних у **одному файлі** на диску, без окремого сервера MySQL | Збереження книг/цитат між запусками |
| **SQLAlchemy** | Перекладач між Python-класами і таблицями БД | Зручної роботи з даними |
| **PyMuPDF** | Бібліотека, яка вміє відкривати PDF, малювати сторінку і діставати текст | Читання PDF і імпорту метаданих |
| **ebooklib** | Бібліотека для EPUB (електронні книги як HTML-розділи) | Читання EPUB |
| **HTML/CSS** | Мова розмітки/стилів; у читачі EPUB текст показується як HTML зі стилями | Нормального вигляду тексту EPUB |
| **Git** | Система версій: історія змін коду, гілки, коміти | Контролю розробки |

Додатково (плюс до ТЗ, можна згадати як розширення):

- **bcrypt** — безпечне зберігання паролів локальних акаунтів;
- **FTS5** — швидкий пошук по тексту книг;
- **Pillow** — обкладинки;
- **pytesseract/Tesseract** — OCR для сканів (опційно);
- **QtCharts** — графіки статистики.

### Крок за кроком перед комісією

1. **Запуск**  
   Показати вікно входу → увійти як `demo`.  
   *Фраза:* «Застосунок настільний, локальні акаунти, дані ізольовані по користувачу.»

2. **Бібліотека**  
   Відкрити «Усі книги», перемкнути сітка/список, фільтр «Читаю зараз» / «Вибране».  
   *Фраза:* «Книги з метаданими, статусами та прогресом.»

3. **Імпорт**  
   «Імпорт книг» → вибрати свій `.pdf` або `.epub` → дочекатись завершення → книга з’являється в бібліотеці.  
   *Фраза:* «Імпорт з локальної файлової системи; файл копіюється в data/books, метадані — в SQLite.»

4. **Метадані**  
   Відкрити деталі книги → редагувати назву/автора/жанр/опис/статус/оцінку/обкладинку.  
   *Фраза:* «Усі основні метадані з постановки задачі.»

5. **Читач**  
   Відкрити книгу. Показати гортання, zoom/шрифт (для EPUB), зміст.  
   *Фраза:* «Вбудований читач: PDF через PyMuPDF, EPUB через EbookLib + HTML у Qt.»

6. **Прогрес**  
   Перегорнути кілька сторінок, закрити читач, відкрити знову — позиція збереглась; на картці видно %.  
   *Фраза:* «Позиція і прогрес пишуться в БД, у тому числі автозбереженням.»

7. **Закладка**  
   Поставити закладку → у меню «Закладки» показати запис → перейти назад у місце.

8. **Цитата**  
   Виділити текст → зберегти цитату → «Цитати» у матеріалах: видно книгу, місце, можна додати коментар/нотатку.  
   *Фраза:* «Окремий модуль цитат, як вимагало ТЗ.»

9. **Нотатка і відгук**  
   Нотатка в читачі; відгук з картки книги (оцінка + текст).

10. **Пошук і фільтри**  
    Верхній рядок пошуку (FTS) і фільтри в бібліотеці за статусом/назвою тощо.

11. **Колекція**  
    «Колекції» → створити колекцію → додати книгу.  
    *Фраза:* «Власні категорії для групування.»

12. **Персистентність**  
    Закрити програму повністю → знову `python run.py` → увійти → показати, що цитати/прогрес/колекція на місці.  
    *Фраза:* «Усе в SQLite і файлах data/, не в оперативній пам’яті.»

Якщо лишиться час — аналітика, backup у налаштуваннях, світла/темна тема.

## 8. Обмеження (краще сказати самим, ніж щоб запитали)

1. Формати лише **PDF** і **EPUB** (не MOBI/AZW).
2. EPUB показується через `QTextBrowser` — без повного Chrome-рушія; дуже складні макети можуть спрощуватись.
3. У PDF цитати зручні, якщо є текстовий шар; для «картинка-скан» потрібен OCR.
4. Це **локальний** застосунок: без хмарної синхронізації між телефонами/ПК.

Після цього одразу: «Але всі вимоги курсової постановки задачі виконані.»

## 9. Типові питання комісії і готові відповіді

### 9.1. Чому два репозиторії / навіщо розділяти бек і фронт?

Щоб розділити відповідальність: інтерфейс можна міняти, не ламаючи логіку БД і навпаки. Це модульність з ТЗ. На практиці GUI імпортує пакет `app` бекенду.

### 9.2. Чому немає REST API / сервера?

Бо це **персональний настільний** застосунок, не веб-сайт. Окремий HTTP-сервер ускладнив би архітектуру без користі для однієї машини. GUI і логіка в одному процесі — швидше і простіше для локальних даних.

### 9.3. Чому SQLite, а не PostgreSQL?

SQLite — файл поруч із програмою, нуль адміністрування, ідеально для offline desktop. Усі дані користувача їдуть разом із `data/`.

### 9.4. Що таке SQLAlchemy?

Це ORM: ми описуємо таблицю як Python-клас `Book`, а бібліотека сама будує SQL. Менше ручних помилок, зручні зв’язки (книга → багато цитат).

### 9.5. Як саме читається PDF?

Модуль `pdf_reader.py` через **PyMuPDF** відкриває файл, може відрендерити сторінку в зображення для показу і витягнути текст для цитат/пошуку.

### 9.6. Як читається EPUB?

`epub_reader.py` через **EbookLib** дістає HTML-розділи; GUI показує їх у `QTextBrowser` зі своїм CSS (шрифт, тема).

### 9.7. Де зберігається прогрес читання?

У таблицях `reading_progress` і `reading_locations` у `library.db`. Читач періодично викликає `save_position`.

### 9.8. Як працює цитата?

Користувач виділяє текст → GUI передає текст + локацію (сторінка/позиція) у `QuoteService` → запис у БД → сторінка «Цитати» вміє показати всі і відкрити місце в книзі.

### 9.9. Як захищені паролі?

Локально через **bcrypt** (хеш, не відкритий текст). Це розширення; сама курсова не вимагала багатокористувацькості, але так безпечніше.

### 9.10. Що буде, якщо імпортувати ту саму книгу двічі?

Рахується **SHA-256** хеш файлу; для того ж користувача дублікат виявляється (унікальність `user_id + file_hash`).

### 9.11. Де модульність у коді?

Шари: `pages` (UI) → `services` → `repositories` → `models`; окремо `readers` і `storage`. Контейнер `AppContainer` збирає залежності в одному місці.

### 9.12. Як довести, що дані живуть між запусками?

Показати демо: створити цитату → закрити `run.py` → відкрити знову → цитата на місці. Пояснити: SQLite-файл на диску.

### 9.13. Який ваш особистий внесок / що найскладніше?

Типові чесні відповіді (оберіть правду під себе):

- інтеграція читача PDF/EPUB в одному UI;
- єдина модель «локації» для закладок/цитат/прогресу;
- зв’язка GUI з сервісами без REST;
- імпорт з метаданими, обкладинками й індексацією пошуку.

### 9.14. Чим ваш застосунок відрізняється від просто відкрити PDF у браузері?

Бібліотека + метадані + статуси + прогрес + цитати/нотатки/відгуки + колекції + пошук по всьому — усе в одній персональній базі, а не «просто переглядач файлу».
